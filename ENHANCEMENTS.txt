Compared with other MiniMax H3 latent upscalers checked on GitHub

================================================================
A. WHAT THE BASE ALREADY DOES (inherited, unchanged)
================================================================
- One node for the full re-enhancement loop: temporal split -> latent
  upscale -> spatial tiling -> per-tile diffusion sampling -> spatial
  stitch -> temporal stitch
- Understands MiniMax H3 nested AV latent (video 24ch + audio 32ch);
  audio passes through untouched
- Peak VRAM bounded to a single tile (works on low-VRAM cards)
- Frame-0 keyframe anchoring between temporal chunks (seam continuity)
- Frozen overlap + fade masks for spatial seams (no seam corruption)
- Two upscale modes: H3 3D upscaler model OR model-free interpolation
- Adaptive architecture detection from checkpoint state dict

================================================================
B. ENHANCEMENTS IN THIS FORK (vs. the base upstream node)
================================================================
1. keep_models_resident flag (NEW INPUT)
   - Boolean on "MMH3 Latent Upscale with Model Params" node
   - ON  = 3D upscaler stays on GPU for the whole pass; the diffusion
     model is NOT unloaded per chunk. Fast path for high-VRAM cards
     (24GB+).
   - OFF = original behavior (unload upscaler to CPU after each chunk,
     offload diffusion model during upscale). Safe default for 12-16GB.
   - Why: the base unloads/reloads the upscaler per chunk and unloads
     the diffusion model for every chunk upscale. On 96GB cards that
     ping-pong is pure wasted GPU transfer time.
   - When resident mode is ON, the upscaler is unloaded ONCE at the end
     of the pass, before returning.

2. LRU model cache (memory safety)
   - Base: _MODEL_CACHE is a plain dict, grows without bound. Loading
     several upscaler checkpoints in one session pins all of them in
     memory forever.
   - Pro: OrderedDict with max 3 entries + LRU eviction
     (move_to_end on hit, popitem(last=False) on overflow).

3. Tile progress bar (UX)
   - Base: the spatial tile loop reports nothing; a 1080p frame with
     512px tiles = 12+ tiles with zero feedback until done.
   - Pro: reports "Tile N/M (row,col)" per tile through ComfyUI's
     progress bar.

4. ComfyUI >= 0.33.0 compatibility fix (CRASH FIX)
   - Base crashes on ComfyUI 0.33.0:
     TypeError: ProgressBar.update_absolute() got an unexpected
     keyword argument 'comment'
   - Pro wraps the call in try/except TypeError and falls back to the
     two-argument form. Works on both old and new ComfyUI versions.
   - Verified working on ComfyUI v0.33.0 (RTX PRO 6000 Blackwell,
     torch 2.13.0+cu130, Python 3.12 conda-forge env).

5. Conditional torch.cuda.empty_cache()
   - Base calls empty_cache() unconditionally even on CPU device.
   - Pro guards it with torch.cuda.is_available().

================================================================
C. COMPARISON WITH OTHER UPSCALE APPROACHES WE CHECKED
================================================================
1. vs. ComfyUI built-in "Upscale Latent" node
   - Built-in: interpolation only (nearest/bilinear/area/bicubic),
     no diffusion re-sampling, does NOT understand H3 nested AV latent
     (breaks the video+audio structure), no tiling, no chunking.
   - This node: full diffusion re-sampling with per-chunk conditioning
     re-anchoring, keeps audio intact, tiled + chunked for VRAM limits.
   - This node also includes a model-free interpolation mode that
     mirrors the built-in but keeps the H3 AV structure.

2. vs. bbaudio-2025/Comfyui-MiniMax-H3-LatentSplit
   - LatentSplit is a PRIMITIVE set (Split/Extract/Append/Anchor nodes)
     you must wire together manually in the graph.
   - UltimateUpscale (base and pro) wraps that whole mechanic into ONE
     node — no graph wiring, no manual seam handling.

3. vs. LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler
   - That node provides the 3D upscaler checkpoint inference only
     (resize the latent once, no re-sampling, no long-video handling).
   - This node consumes the same checkpoints (latent_upscale_models
     folder) AND adds the temporal + spatial + re-sampling pipeline on
     top, so long/high-res clips work on any VRAM.

4. vs. pixel-domain video upscalers (SeedVR2, NVIDIA RTX VSR-Pro,
   frame-interpolation packs)
   - Those upscale DECODED pixels after the VAE: they cannot use the
     diffusion model or the conditioning, and they re-encode.
   - This node works IN LATENT SPACE before VAE decode: the H3 model
     itself re-samples every tile with the original conditioning, which
     reconstructs detail instead of sharpening pixels. Audio stays
     latent-native the entire way.

================================================================
D. KNOWN LIMITS (unchanged from base, honest list)
================================================================
- Single-video latent only (batch 1)
- No resume/checkpoint across an interrupted run
- Per-chunk resolution must be uniform (no progressive multi-scale)
- The 3D upscaler only upscales (effective scale >= 1.0)
- Target width/height must match the conditioning's generation size
